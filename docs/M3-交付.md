## 能力

- 人物页：按书筛选/搜索，人物网格；姓名、别名、身份、简介（简版 Markdown）、标签、颜色、头像完整增删改查

- 正文标记：
  - 最长优先、别名参与、默认忽略单字名、不做分词
  - 当前章节内所有出现处按人物颜色画**虚线**（不包围、不改变原文）
  - 翻章/换书/改人物/开关变化自动重扫；设置页与人物页都能全局关闭
  - TXT 用 `<span class="char">`；EPUB 用 epub.js `annotations.underline`（SVG，不改 DOM）
- 悬停/点击：桌面悬停 250ms 出卡（头像/姓名/别名/身份/简介/标签/3 张插画/打开档案），点击名字打开右侧档案抽屉；滚动/翻页自动关；卡片夹在视口内
- 档案抽屉：头像、姓名、别名、身份、简介、标签、插画库、出场章节、相关笔记
- 插画库：上传 / Ctrl+V 粘贴 / 多选；Blob 存 IndexedDB；自动缩略图；大图查看（左右切换）；删除；前后排序；设头像
- P1：出场章节（按章扫描并缓存，点击跳转）；笔记关联人物（`Note.characterIds`，档案页聚合）
- 删除人物：解除正文标记与笔记关联，不删笔记；插画与出场缓存一起清理

在 `epub-3章.epub` 第一章上对比：

| 方案 | 结果 |
|---|---|
| **A：epub.js annotations.underline(cfiRange)** | 11 处标记 **3.1ms**；已存在的笔记高亮仍在；笔记 CFI 解析文本前后一致（`山雨落在旧渡口，`）；点击回调命中；删掉标记后笔记高亮剩 1 条；DOM 未改（`span.char-mark=0`） |
| **B：DOM 包 span** | 11 处 **0.3ms**，但同一笔记 CFI 解析出的文本变成 `落在旧渡口，木桩上积着薄薄一层水。`（偏移 2 个字）；重新计算的 CFI 变化 `/4/4,/1:0,/1:8` → `/4/2,/1:0,/1:6`；保存的 CFI 跳转位置随之漂移 |

**选 A**：不改 iframe DOM，CFI 与 M2 笔记完全兼容；用 marks-pane 的 `<line>` + 外层 CSS 画虚线（`stroke-dasharray: 2 2`，颜色走 `--char-mark-color`）。B 会破坏已有笔记定位，不采用。

## 已知问题

1. EPUB 的人名标记是 marks-pane SVG，覆盖在文字上；若同一段文字同时有笔记高亮，点击命中最后添加的标记（通常是人名）。重叠处的点击目标可能不是笔记。
2. 出场章节扫描「失效即重扫」：会重新解包并逐章扫描，5MB / 230 章 EPUB 打开抽屉时有一次等待；结果写入 IndexedDB 后再次打开就很快。
3. 启动时一次性读出全部人物插画 Blob（只是引用，不全部解码）；几千张图片时应改成分页/懒加载。
4. 单字名只有全局「默认忽略」，没有单人物「允许标记」开关；也没有「此词不再匹配」黑名单（设计稿里的 P1）。
5. TXT 目前只有人物标记与建卡，没有划线/笔记（M2 笔记仍是 EPUB 专属）。
6. 头像只能从插画里选或上传原图，没有裁剪框。
7. E2E 的「重启」仍是 `webContents.reload()`（同 M2），不是跨 Electron 进程重启；读取路径一致。
8. `epub-人物.epub` / `epub-无封面.epub` 是 M3 专用样本，没有写进 manifest，避免改变 M2 的样本数量断言。
