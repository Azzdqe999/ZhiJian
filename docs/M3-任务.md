# M3 任务书 · 人物系统（TXT + EPUB）

状态：未开始
目标：把「人物卡」从 M0 的静态演示变成真功能：建卡、别名、正文标记、悬停卡、档案页、插画库。
**用户主读 EPUB，EPUB 路径优先；TXT 同步做齐。**

## P0（必须）

1. 人物页（左侧导航「人物」不再是占位）：
   - 按书筛选，人物网格/列表；新建、编辑、删除。
   - 字段：姓名、别名（多个）、身份、简介（Markdown 简版）、标签、颜色、头像。
2. 从正文建卡：
   - TXT 选中文字 → 工具条「标为人物」。
   - EPUB 选中文字 → 现有划词工具条加「标为人物」。
   - 若姓名/别名已存在，提示「加入某人的别名」或「另一个人」。
3. 正文标记：
   - 当前章节内所有姓名/别名出现处标虚线（颜色按人物）。
   - 翻章、换书自动重扫；可在设置里全局关闭标记。
   - 匹配规则：最长优先；别名参与；默认忽略单字名；不做分词。
4. 悬停/点击：
   - 桌面悬停 250ms 出卡：头像、姓名、别名、身份、简介、标签、3 张插画缩略图、「打开档案」。
   - 点击名字打开右侧档案抽屉（不打断阅读位置）。
5. 档案抽屉：头像、姓名、别名、身份、简介、标签、插画库、相关笔记（若已关联）。
6. 插画库：上传/粘贴/多选；IndexedDB 存 Blob；缩略图；大图查看；删除；排序；设头像。

## P1（顺手做）

7. 人物页显示「出场章节」列表（按章节扫描缓存），点击跳转。
8. 笔记可关联人物（Note 增加 characterIds），档案页聚合相关笔记。
9. 删除人物时解除正文标记，不删笔记。

## EPUB 标记的关键风险（先 spike）

改 DOM 包 `<span>` 可能让 epub.js 的 CFI 失效，进而破坏已有高亮/笔记。两条路线必须先用最小 spike 对比：

- A：用 epub.js `annotations.highlight(cfiRange, ...)` 做人名标记（不改 DOM，CFI 安全；但每章几十个 SVG 标注，注意性能与 hover 命中）。
- B：DOM 包裹 + 重新应用笔记高亮，验证 CFI 是否仍能恢复。

选一条，在 `app/spike/` 留最小复现，汇报里说明理由。**若两条都不行，先做 TXT，EPUB 只做「档案页」不做正文标记，并明确告知。**

## 数据模型

```
Character { id, bookId, name, aliases[], role, bio, tags[], color, avatarImageId?, createdAt, updatedAt }
CharacterImage { id, characterId, blob, caption, sort, createdAt }
Note { ...existing, characterIds?: string[] }
```
IndexedDB 新增 stores：`characters`（index bookId）、`characterImages`（index characterId）。

## 验收

1. 人物页可增删改查，字段完整，按书筛选。
2. TXT 与 EPUB 都能从选中文字建卡；同名/别名有合并提示。
3. 当前章节全部出现处有虚线标记；翻章自动重扫；可关闭。
4. 桌面悬停出卡、点击开档案；卡片定位不遮挡、不越界。
5. 插画可上传/粘贴、看大图、删除、排序；重启后仍在。
6. 50 人物 × 5000 字章节，标记 < 50ms；翻页不卡。
7. M1 51 项、M2 53 项测试仍全过；E2E 增加人物路径。
8. M2 修复 10/11/12 逐条验证。
